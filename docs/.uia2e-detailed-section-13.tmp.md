# 第十三节：UI-A2E 最终文档收口与 Seal

## 13.1 本节目标

这一节是 UI-A2E 的最后一节。

它不再新增 Blueprint 播放逻辑，而是在第十二节 Scenario A-E 全部实际通过后，把：

```text
实现状态
PIE 验收证据
Blueprint 保存快照
验证日志
A2E 总体契约
后续路线图
```

统一收口，最终将阶段状态从：

```text
UI-A2E = PARTIAL
```

推进到：

```text
UI-A2E = COMPLETE / VALIDATED / SEALED
```

并在 UI-A2 没有其他未完成子阶段的前提下，同步将：

```text
UI-A2 = COMPLETE / SEALED
```

然后才允许进入：

```text
UI-A3-1 Dynamic Text
```

禁止在 A2E 尚有局部 FAIL、未跑 PIE、文档状态互相矛盾或 Blueprint 未保存时提前写 `SEALED`。

## 13.7 最终快照必须能证明的 Router 覆盖

检查 `BeginPresentationRecordPlayback`，确认正式可见 Record 集合全部有明确行为：

```text
CardPlayed
Damage
BlockChanged
EnergyChanged
CardZoneChanged
DeckShuffled
StatusChanged
Victory
Defeat
ResolutionFault
```

其中：

```text
None
```

仍不应被当成可见 async Record。

每个可见类型都应满足二选一：

```text
合法支持子类型
→ Blueprint async playback
→ Return true

不合法 / 无法安全表现 / identity 不匹配
→ Return false
→ C++ immediate fallback / Controller 正常收敛
```

不得存在“看似接入但启动失败仍 Return true”的路径。

## 13.8 最终快照检查 `FinishPresentationRecord`

最终 `FinishPresentationRecord` 必须对所有 Blueprint 实际接管的 async 类型有明确完成路径。

```text
CardPlayed

BlockChanged
EnergyChanged
CardZoneChanged
DeckShuffled
StatusChanged
Victory
Defeat
ResolutionFault
```

每个路径最后都应进入统一 exact-token 完成逻辑，且正常 Finish 不做 Before 恢复。

重点禁止：

```text
Damage Finish 恢复 HPBefore
Status Update Finish 恢复 AmountBefore
Energy Finish 恢复 EnergyBefore

```

正常完成语义始终是：

```text

→ Notify
→ reducer
→ formal After
```

# 第十三节 I：Fail / 回退规则

## 13.29 任一最终检查失败时如何处理

不要为了“已经做到最后一步”而继续 Seal。

按失败类型回到对应章节：

```text
Status duplicate / identity
→ 第一～第六节

Energy duplicate / flashback
→ 第七节

CardZoneChanged 顺序 / hand 残留
→ 第八节

→ 第九节

Terminal 错序 / 覆盖
→ 第十节

Cancel / stale transient
→ 第十一节

跨 Record 顺序 / stuck Resolving
→ 第十二节
```

修复行为后：

```text
Compile + Save
→ 重跑受影响局部 PIE
→ 重跑受影响 End-to-End Scenario
→ 更新证据
→ 再进入第十三节
```
